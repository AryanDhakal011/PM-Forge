# Product implementation decisions

- **Retain the repository and Next.js 16.4.3.** The user asked to continue the existing product and visual system. Relevant bundled Next.js client/server, route, page-param, CSS, and metadata guides were read before implementation.
- **Treat handoff documents as design/content specifications.** Their embedded prompts for a different coding agent are not independent user authorizations. The current request authorizes product routing and account work that had been out of scope in the earlier scroll-only phase.
- **Local-first is the usable default.** Dexie/IndexedDB provides the full guest loop without an account, secret, or paid service. A browser-local profile is never described as server authentication.
- **Use a genuine auth library.** Better Auth's current [Next.js integration](https://better-auth.com/docs/integrations/next) and [SQLite adapter](https://better-auth.com/docs/adapters/sqlite) support the local Node runtime. The configured path was exercised with signed test sessions; actual provider credentials remain user-managed.
- **Do not invent Cloudflare deployment.** [OpenNext's Cloudflare documentation](https://opennext.js.org/cloudflare) supports the installed Next.js generation, but the repository has no provisioned D1 binding, OAuth setup, or Workers deployment configuration. The local implementation uses Next route handlers + Node SQLite so it is runnable now. A real D1 adapter/deployment is explicitly deferred, rather than silently presenting SQLite as D1 or fabricating sync.
- **Use restrained 3D where it communicates state.** The direct user request for GSAP/Three.js and an immersive PM world overrides the document's blanket app-3D prohibition. The desktop instrument is lazy and demand-rendered; mobile/reduced-motion are still drawings; data workbenches stay semantic and accessible.
- **Preserve content honesty.** All 63 supplied questions stay draft. Public figures are not promoted to verified facts without rechecking their primary sources. Proposed rubric weights/bands remain labelled as proposals. Behavioral scores estimate structure, never truthfulness.
- **Use an adapted engine, not a second framework.** The existing Next/React/GSAP/Three stack is retained. Pure transition/scoring functions are separate from content, storage, and UI. All categories share the run shell while exposing category-specific controls.
- **Keep consent explicit.** Preview carry-forward stages a small, versioned 24-hour reference manifest instead of duplicating large answers. Import creates Demo records only after consent. Guest migration is idempotent and never silently merges another profile. Logout/device reset and server-account deletion are separate operations.
- **Guard account boundaries on the server.** Every workspace read/write uses the actual authenticated session's user ID. Inputs are strict/size-capped; writes check Origin and workspace version. Expired/offline sessions leave the device copy usable. The in-memory local rate limiter is not claimed to be a distributed production control.
