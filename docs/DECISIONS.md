# Real World Projects decisions

The supplied `PMForge_Real_World_Projects_Handoff_v1.txt` is the product reference for this module. It does not independently authorise deployment, external messages, account creation or credentials. The current user request authorises implementing the section in the existing local product.

| ID | Implementation |
| --- | --- |
| R1 | Public `/projects` overview and full `/app/projects` campaign namespace. |
| R2 | Fixed three-chapter campaigns; no LLM or generated plot. |
| R3 | Five bounded variables per campaign, explicit choice deltas and deterministic conditional carry rules. |
| R4 | All 12 campaigns available without skill-level gates; one role/practice-based recommendation. |
| R5 | Debrief exposes the exact causal trail, not a numeric grade. |
| R6 | Shared GSAP/SVG entrance factory, 8.5 seconds, skip at 2.5, reduced motion 300 ms. |
| R7 | Decision weight determines pacing; no forced decision timer. |
| R8 | Costs are named before lock, earlier commitments appear as later constraints, and canonical history is validated. |
| R9 | Campaigns can be repeated; branching never replaces the original timeline. |
| R10 | Local transactional drafts plus the existing signed-session workspace sync. D1 is not provisioned. |

Guest-local continuity is retained deliberately, despite the handoff’s account-only language, because the current product already supports guest Interview runs and live provider credentials are absent. Account APIs continue to require real signed sessions. No local flag is treated as authentication.

The handoff does not supply numerical initial values/delta vectors or full evidence text for 36 chapters. Those details are authored implementation additions, explicitly simulated and awaiting independent review. Last Mile’s absorbed-loss contradiction is resolved by charging the platform’s financial-pressure variable; all choices preserve the stated safe-route boundary. Destructive character animations and text sentiment scoring are replaced with readable state-driven posture changes and explicit framing choices.

Project free-form rationale requires opt-in for account sync and is redacted on both client and server by default. Local and explicit user-triggered exports retain it. Project snapshot validation reconstructs the authored trail and rejects invented reactions or state.
